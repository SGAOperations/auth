# CLAUDE.md

Conventions for coding agents and contributors. This file points at the docs that hold the rules; it does not restate them.

## What this is

SGAuth is the central authentication service for SGA products. The stack is listed in the header of [`docs/ENGINEERING.md`](docs/ENGINEERING.md).

## Read first

- [`docs/ENGINEERING.md`](docs/ENGINEERING.md): the quality bar, and the pre-pull-request checklist in §8.
- [`docs/sgauth-design/SGAuth-design-summary.md`](docs/sgauth-design/SGAuth-design-summary.md): the settled architecture. It wins over `ENGINEERING.md` where they disagree.
- [`docs/sgauth-design/SGAuth-red-team.md`](docs/sgauth-design/SGAuth-red-team.md): the threat review.
- [`CONTRIBUTING.md`](CONTRIBUTING.md): CI checks, fixing a `migrations` failure, branch protection.
- [`README.md`](README.md): environment setup, Neon branches and roles.
- [`docs/MIGRATIONS.md`](docs/MIGRATIONS.md) and [`docs/ENVIRONMENTS.md`](docs/ENVIRONMENTS.md): where each schema command may run, and what each environment is.

## Neon only

No Supabase code, dependency, env var or API call, for any purpose. See [`ENGINEERING.md` §1](docs/ENGINEERING.md#1-architecture).

## Commands

| Task                  | Command                                                                             |
| --------------------- | ----------------------------------------------------------------------------------- |
| Dev server            | `npm run dev`                                                                       |
| Tests (Vitest)        | `npm test`                                                                          |
| Lint                  | `npm run lint`                                                                      |
| Format / check format | `npm run format` / `npm run format:check`                                           |
| Typecheck             | `npx prisma generate`, then `npx tsc --noEmit`, in that order (ENGINEERING §8)      |
| New migration         | `npm run prisma:migrate-dev -- --name <change>` (guarded; see `docs/MIGRATIONS.md`) |
| Seed                  | `npm run seed` (runs `prisma/seed.ts` via the `prisma.config.ts` seed command)      |

## Layout

- `src/app/`: routes. `api/auth/[...all]` is the Better Auth handler.
- `src/lib/`: server code. `src/lib/auth/` holds the Better Auth config.
- `src/components/ui/`: shadcn primitives, added with the CLI.
- `src/generated/`: the generated Prisma client. Never edit it.
- `prisma/`: schema, migrations, seed.
- `docs/sgauth-design/`: design sources. `out/` is generated by `build.mjs`.
- `docs/runbooks/`: operational runbooks.
- `scripts/`: repository scripts. `port-*.mjs` are vendored pipeline scripts.

## New mutating route or server action

It must meet [`ENGINEERING.md` §3](docs/ENGINEERING.md#3-security) and the route-handler items of [§8](docs/ENGINEERING.md#8-pre-pull-request-self-check): zod input, `authz.ts` checks server-side, Origin enforcement, and an `AuditEvent`.

## Tests

Vitest. Tests sit next to the code as `*.test.ts`, as in `src/lib/auth/`. Security logic ships with tests per [`ENGINEERING.md` §7](docs/ENGINEERING.md#7-quality-bar).

## Commits and PRs

- Branch from `dev` and open the PR against `dev`.
- Commit subjects start with the issue number (`#17 add migrations ...`, as in the history).
- The PR body has `Closes #<n>`.
- Apply one change-type label from `bug`, `feature`, `chore`, `docs`, `refactor`. Check `gh label list`; don't invent labels.
- **No model attribution.** Commits, pull requests and issue comments in this repository carry no AI-model attribution: no `Co-Authored-By: Claude …` (or any model) trailer, and no "Generated with Claude Code" or similar footer. This applies to direct sessions and to the port pipeline's stage agents alike, and overrides any tool default that adds them.
