# Engineering Standards

Every pipeline agent reads this document before working. It defines the quality bar beyond what is obvious from the code. Plans must account for it per feature, implementations must follow it, and review findings may cite its sections the same way they cite the plan.

**Boundary with design.** This repository has no design document yet: its interface is stock shadcn/ui with no first-party screens. Interface rules will live in a separate `DESIGN.md` once there is enough UI to describe. Accessibility belongs here when it is written, not there.

**Where the architecture comes from.** SGAuth's settled design is in [`docs/sgauth-design/SGAuth-design-summary.md`](sgauth-design/SGAuth-design-summary.md), the threat review in [`SGAuth-red-team.md`](sgauth-design/SGAuth-red-team.md), and the ticket set in `docs/sgauth-design/tickets-auth.mjs`. Rules below tagged _(design)_ are carried from the summary. They describe the system being built, and the current code is a thin scaffold that predates most of them. Where the summary and this document disagree, the summary wins and this document is stale.

**Stack:** TypeScript (strict) · Next.js 16 App Router · React 19 · Prisma 7 with `@prisma/adapter-pg` on Neon Postgres · Better Auth 1.7.x _(design, not yet installed)_ · Tailwind CSS 4 with shadcn/ui (`base-nova`) · Vitest and Playwright _(planned in the ticket set, not yet installed)_ · Vercel hosting.

## 1. Architecture

- **Routes live in `src/app/` using App Router conventions**: pages as `page.tsx`, HTTP endpoints as `route.ts` exporting method handlers.
- **Shared server code lives in `src/lib/`** (`src/lib/prisma.ts`, `src/lib/utils.ts`).
- **UI primitives live in `src/components/ui/` and are added with the shadcn CLI**, configured by `components.json` (style `base-nova`, aliases `@/components`, `@/lib`, `@/hooks`). Do not hand-write a primitive that shadcn provides.
- **Cross-directory imports inside `src/` use the `@/*` alias** (`tsconfig.json` `paths`; every file in `src/components/ui/` imports `@/lib/utils`).
- **Class names are merged with `cn()` from `@/lib/utils`**, never by string concatenation (all 9 files in `src/components/ui/`).
- **Do not add new Supabase code** _(design: "SGAuth does not use Supabase for any purpose")_. The Supabase scaffold (callback route, `@supabase/*` dependencies, `supabaseUserId`, `supabase/`, README setup) has been removed. Don't reintroduce any of it.
- **Authentication is Better Auth with `@better-auth/prisma-adapter`** _(design)_. Do not hand-roll session, password-hashing or cookie logic that Better Auth provides.
- **`docs/sgauth-design/out/` is generated by `node docs/sgauth-design/build.mjs`.** Edit the `tickets-*.mjs` sources and regenerate; never hand-edit `out/` (it is Prettier-ignored for this reason, per `069bba5`).

## 2. Data and integrity

- **One Prisma client, from `src/lib/prisma.ts`.** It is a `globalThis` singleton built on `PrismaPg`. Application code imports `prisma` from there and never constructs `PrismaClient` itself. `prisma/seed.ts` is a standalone script and is the exception.
- **Runtime uses the pooled `DATABASE_URL`; Prisma CLI and migrations use the direct `DIRECT_URL`** via `prisma.config.ts` (`src/lib/prisma.ts`, `prisma.config.ts`, `.env.example`; _(design)_ Neon pooled vs direct).
- **Schema changes go through `prisma migrate`.** Each change lands as a new directory under `prisma/migrations/`, and committed migrations are never edited (`prisma/migrations/20260330032232_init/`).
- **The generated client in `src/generated/prisma/` is build output.** It is gitignored and ESLint-ignored (`.gitignore`, `eslint.config.mjs`), and is never committed or edited.
- **Request input is parsed with zod before use** in every route handler and server action. Never read raw request JSON, form data or search params into business logic unparsed. _(proposed, approved)_
- **Environment variables are read only through `src/lib/env.ts`** (zod-parsed). No other file under `src/` or `prisma/` reads `process.env` directly, and an ESLint rule enforces it. `env` is server-only at runtime, `publicEnv` holds `NEXT_PUBLIC_*` variables only, and every variable's shape lives in `src/lib/env-schema.ts`. Add a new variable there and to `.env.example` with a comment saying what it is for. _(proposed, approved)_
- **Products key on the SGAuth user id (UUID v7)**; email and name come from the session _(design)_.
- **Users are never hard-deleted.** Removal is deactivation (soft) or a tombstone (status `DELETED`, PII scrubbed, id kept) _(design)_.
- **Admin invariants are enforced in two places:** the pure `authz.ts` module, and Postgres constraints or triggers as a backstop, for example the partial unique index on the single Primary Admin _(design)_.

## 3. Security

- **Any `src/lib` module that touches the database, secrets or environment variables begins with `import "server-only"`**, as `src/lib/prisma.ts` does, except `src/lib/env.ts`, which is guarded at runtime instead. _(proposed, approved)_
- **Secrets never get a `NEXT_PUBLIC_` prefix and never reach client components** (`.env.example`: service-role key "never expose to the client").
- **Authorization decisions are made by pure functions in `src/lib/authz.ts`**, called server-side by every handler that needs them. The UI may hide controls, but it never enforces anything _(design)_. Admins grant or revoke admin for others only: never for themselves, and never on the Primary Admin.
- **Every mutation enforces Origin/Referer** against the product registry. SameSite=Lax still sends the shared cookie on sibling-subdomain POSTs _(design)_.
- **Emailed links consume their token on POST, never on GET.** The GET renders a confirm step, because Microsoft Safe Links pre-fetches links _(design)_.
- **Auth responses are enumeration-resistant.** Sign-in, sign-up, reset and set-password do not reveal whether an account exists _(design)_.
- **Redirect targets (`/logout?redirect=` and similar) are validated against the product registry**, never passed through _(design)_.
- **The session cookie is set on `Domain=northeasternsga.com` with the `__Secure-` prefix, HttpOnly, Secure, SameSite=Lax, and no cookie cache** _(design)_. Do not change these attributes without a design change.
- **Rate limiting (Upstash) covers sign-in, sign-up, reset, token, re-auth and admin endpoints, and not the session endpoint.** It **fails open with an alert** on an Upstash outage. Better Auth's DB limiter stays disabled _(design)_.
- **Every privileged or security-relevant action writes an `AuditEvent` from the typed catalog.** The table is append-only, and audit rows never carry PII beyond what the catalog defines _(design)_.

## 7. Quality bar

- **TypeScript `strict` is on** (`tsconfig.json`), and `npx tsc --noEmit` must pass (CI `typecheck` job).
- **No `any` casts.** Fix the type instead. An unnecessary cast was removed in `df0bfaa`, and `@typescript-eslint/no-explicit-any` is a lint error under `eslint-config-next/typescript`.
- **ESLint is `eslint-config-next` core-web-vitals + typescript, with `eslint-config-prettier`** (`eslint.config.mjs`). `npm run lint` must pass.
- **Formatting is Prettier with the repository config** (`.prettierrc`: semicolons, double quotes, trailing commas, width 80), and `npm run format:check` must pass. Run `npm run format` rather than hand-formatting.
- **Changes to authorization, session, token, lockout or rate-limit logic ship with unit tests** (Vitest, once the test-runner ticket lands). A pure-function module like `authz.ts` gets a test for every rule it encodes. _(proposed, approved)_

## 8. Pre-pull-request self-check

Each item comes from something that has already gone wrong in this repository's history.

- [ ] `npm run format:check` passes, including on generated or CLI-added files (shadcn components failed it in `7286f02`, and the design sources in `069bba5`). Run `npm run format` after any `shadcn add`.
- [ ] `npx tsc --noEmit` passes **after** `prisma generate`. The typecheck needs the generated client, and CI generates it explicitly because it installs with `--ignore-scripts` (`6c97a7d`, `3b4984d`).
- [ ] Any dependency change updates `package-lock.json` in the same commit, and paired `@types/*` versions match their runtime package (`818f1a5`, `af9bc40`).
- [ ] No `any` casts, and no new `eslint-disable` without a stated reason.
- [ ] Nothing under `src/generated/` or `docs/sgauth-design/out/` was hand-edited or committed outside its generator.
- [ ] No new Supabase import, dependency, env var or API call.
- [ ] Every new route handler or server action parses input with zod, runs `authz.ts` checks server-side, and enforces Origin on mutations.
- [ ] Every new `src/lib` module that touches the DB, secrets or env starts with `import "server-only"`, and reads env through `src/lib/env.ts`.
- [ ] New env vars are added to `.env.example`, and none that hold secrets are `NEXT_PUBLIC_`.
- [ ] Security-relevant actions emit an `AuditEvent`, and security logic changes ship with tests.
